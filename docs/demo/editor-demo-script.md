# 寫作編輯器 Demo 腳本（給指導教授看的錄影流程）

> 對象：指導教授｜語言：繁體中文 UI｜預估長度：8–12 分鐘
> 本地網址：編輯器列表 `http://localhost:3000/zh-Hant/editor`
> 範例草稿：`docs/demo/sample-thesis-draft.md`（已刻意埋入缺陷、純文字引用、文法問題，方便展示 AI 功能）

---

## 0. 錄影前置檢查（錄影前自己先跑一次，別錄進影片）

1. **確認服務都起來**：
   ```bash
   docker compose ps          # neo4j / backend / frontend 三個都 Up，neo4j 顯示 healthy
   ```
   開瀏覽器到 `http://localhost:3000/zh-Hant/editor`，應該看到空的「我的文件」列表（已清空，0 篇）。

2. **暖機 Neo4j（重要）**：全新環境第一次「缺陷檢查」會建知識圖譜，偶爾第一槍丟 `TransientError`。錄影前先匯入草稿、跑一次缺陷檢查（成功就好），再把那份草稿刪掉。正式錄影時就不會卡。
   - 本次驗證時第一槍就成功了，但仍建議暖機保險。

3. **介面狀態**：
   - 右上角語言切到 **繁體中文**。
   - 深色／淺色模式依喜好先決定（建議淺色，投影/錄影較清楚）。
   - 視窗放大到 1440 寬以上，工具列才會完整展開。

4. **引用搜尋的小技巧**：引用搜尋用「英文關鍵字」效果最好（中文 claim 不會做語意重排，結果排序會比較亂）。Demo 時請用英文查詢，例如 `attention is all you need transformer`。

5. 準備好 `sample-thesis-draft.md` 在桌面，待會「匯入」用。

---

## 場景 1 — 匯入草稿、文件管理、自動儲存

**操作**
1. 在「我的文件」頁，點右上 **匯入文件（Import）** → 選 `sample-thesis-draft.md`。
2. 系統解析後自動建立文件並跳進編輯器，標題自動帶入「基於知識圖譜的學術論文邏輯缺陷自動偵測方法」。
3. 點一下標題列，隨意改幾個字 → 觀察右上 **儲存狀態徽章** 從「儲存中」變「已儲存」。
4. （可選）回列表頁，展示每篇文件有「更新時間」與刪除鈕。

**預期**：草稿完整呈現，左側大綱自動列出各章標題。
**講解重點**：「支援 .md / .docx / .tex / .txt 匯入；編輯即時自動存檔，不用按儲存。」

---

## 場景 2 — 基本排版與 Slash 選單

**操作**
1. 工具列示範：選一段文字按 **粗體 / 斜體**、切 **H1/H2/H3**、插入 **項目清單**。
2. 在空白行輸入 `/` 叫出 **Slash 選單**，依序插入：
   - `/表格`（table）→ 插入表格，游標進儲存格時會跳出表格工具列。
   - `/數學`（math）→ 插入 LaTeX 公式，例如 `\hat{y}=\mathrm{softmax}(QK^\top/\sqrt{d})`。
   - `/目錄`（toc）→ 自動產生目錄。
   - `/參考文獻`（references）→ 自動產生格式化參考文獻清單。
3. 示範右側 **引用樣式** 下拉（APA / IEEE / Chicago / Harvard / Vancouver / Numeric），切換後參考文獻清單格式即時改變。

**講解重點**：「所見即所得，學術元素（公式、表格、目錄、參考文獻）都是原生區塊，不是貼圖。」

---

## 場景 3 — 大綱導覽、尋找取代、寫作進度

**操作**
1. 點左側 **大綱** 任一標題 → 編輯器跳到該章。
2. 按 `Cmd/Ctrl + F` 叫出 **尋找/取代**，搜「方法」看高亮與 `N/M` 計數，示範「全部取代」。
3. 點標題列右側 **寫作進度（靶心圖示）** → 顯示總字數；輸入字數目標（如 20000）→ 出現進度條與各章字數分佈。

**講解重點**：「長文寫作的導航與進度掌控，章節字數一目了然。」

---

## 場景 4 — AI 自動補全（Ghost Text）

**操作**
1. 在某段句尾接著打字，例如打「本研究提出一套自動化的論文邏輯缺陷偵測系統，其核心貢獻在於」。
2. 停頓約 1 秒 → 出現灰色 **ghost text** 建議（或直接按 `Cmd/Ctrl + J` 立即觸發）。
3. 按 `Tab` 接受、`Esc` 拒絕。
4. 點工具列 **AI 模式（Sparkles）** 切換 Auto → Manual → Off，說明可關閉。

**講解重點**：「像 GitHub Copilot 的寫作版，會讀整篇上下文與大綱給建議。」

---

## 場景 5 — 改寫面板（Rewrite）

**操作**
1. 選取一句口語化的句子，例如「實驗顯示本方法的效果非常好，使用者滿意度極高。」
2. 浮動選單點 **改寫** → 開右側改寫面板。
3. 點預設指令 **學術化（academic）** → 即時串流出改寫結果（實測會變成「實驗結果顯示，本方法具有良好的效果……」）。
4. 也示範自訂指令，輸入「縮短成一句並加上量化語氣」→ 重新生成。
5. 按 **採用** 取代原文，或 **捨棄**。

**講解重點**：「七種預設（改寫/簡化/擴寫/精簡/通順/學術化/修文法）＋自由指令，結果先預覽再採用。」

---

## 場景 6 — 大綱生成器（Outline Generator）

**操作**
1. 工具列點 **大綱（ListTree）** 開面板。
2. 上半：點 **IMRaD 範本** → 一鍵插入 緒論/文獻探討/方法/結果/討論/結論 標準骨架。
3. 下半：輸入主題「基於知識圖譜的論文邏輯缺陷偵測」→ 按 **生成** → 串流產出客製化標題樹（實測產出約 20+ 條多層標題）→ **插入**。

**講解重點**：「從零開始寫論文時，先用 AI 把章節骨架搭好。」

---

## 場景 7 — 智慧引用：搜尋 → 插入 → 驗證 → 溯源

> ⚠️ 用英文查詢效果最好。

**操作**
1. 工具列點 **引用搜尋（放大鏡）** 開面板。
2. 搜尋框輸入英文：`attention mechanism long-range dependencies transformer` → 搜尋（資料來源 OpenAlex / Crossref）。
3. 結果卡片會依語意相似度排序（實測 Transformer-XL、Attention Mechanisms 等相關文獻排前面，附 similarity 分數）。
4. 在想引用的句子後，點某篇的 **插入** → 文中出現引用 chip。
5. 點該引用的 **驗證（紅綠燈）** → 系統判斷這篇摘要是否支持你的主張：
   - 綠＝supports、黃＝partial、紅＝unsupported，並附「證據句＋理由＋信心值」。
6. 點 **溯源（Ground）** → 抓全文，列出最支持主張的句子（若該文有開放全文）。

**講解重點**：「不只找引用，還會幫你檢查『這篇真的支持你這句話嗎』——對抗 AI 幻覺式亂引。」
**誠實補充**：溯源需要該論文有開放取用全文，閉源論文會退回只用摘要或顯示無全文。

## 場景 8 — 引用重新連結（Relink）＋ 批次驗證

**操作**
1. 草稿底部有純文字 `## 參考文獻` 清單，內文也有 `(Vaswani et al., 2017)` 這種純文字標註。
2. 引用面板點 **重新連結（Relink）** → 系統解析參考文獻、到 OpenAlex 比對，把純文字引用升級成可驗證的活引用節點。
   - 實測：解析 3 筆、其中 2 筆學術文獻、成功比對 Vaswani 並連結內文 1 處。
3. 工具列點 **驗證全部引用（BadgeCheck）** → 批次對所有活引用跑紅綠燈。

**講解重點**：「從 Word/舊稿匯入的死引用，可一鍵救回成可查證的引用。」
**誠實補充**：比對門檻保守（標題相似度 ≥ 0.80 才連），比對不到的會保留純文字，不會亂連。

---

## 場景 9 — 缺陷檢查（Thesis Critic）＋ 一鍵 AI 修正 ⭐ 核心賣點

**操作**
1. 工具列點 **缺陷檢查（盾牌 ShieldAlert）** → 對整篇跑檢查（依章節切，含跨章節規則）。
2. 等待數秒，右側 **缺陷面板** 列出問題，每條含：規則代號（REL-xx）、嚴重度色塊、說明、建議。
   - 實測本草稿會抓到：
     - **REL-01** 主張無證據（「可用於教學現場」沒給依據）
     - **REL-06** 概念未形式化（GraphRAG「精準度」沒定義）
     - **REL-04 / REL-08**（跨章節，高嚴重度）問題拆解 / 問題-解法對應失聯
     - **REL-12** 結論未回扣核心主張
3. 點某條缺陷的 **定位** → 編輯器高亮對應句子並跳過去。
4. 點 **AI 修正（Sparkles）** → 自動帶著「依這條缺陷修正」的指令開改寫面板並生成修正稿 → 採用。

**講解重點**：「這是整套系統的核心——不是抓錯字，而是抓『論證結構』的問題：主張有沒有證據、章節之間有沒有對上。這正是論文 review 最花教授時間的部分。先把論文拆成知識圖譜，再用 13 條規則檢查，所以講得出『為什麼這裡有問題』。」

---

## 場景 10 — 文法 Lint（中文學術寫作規則）＋ 一鍵修正

**操作**
1. 工具列點 **Lint（拼字檢查圖示）** → 即時掃描（純規則、不花 token）。
2. 面板會列出三類問題（本草稿都有）：
   - **halfPunct**：中文旁邊用了半形標點（如「成功,Transformer」的半形逗號）。
   - **pangu**：中英文之間沒空格（如「使用GraphRAG技術」「BERT模型」）。
   - **spaceBeforePunct**：標點前多了空格。
3. 點單條 **定位** 高亮；點 **修正** 套用；或點 **全部修正** 一次清乾淨。

**講解重點**：「中文論文常見的標點/空格瑕疵，規則式即時抓、一鍵修，零成本。」

---

## 場景 11 — 版本歷史：建立快照 → 還原

**操作**
1. 工具列點 **版本歷史（History）** 開面板。
2. 上方輸入名稱「Demo 版本快照」→ **儲存** 一個版本（系統也會每約 2 分鐘自動快照）。
3. 故意刪掉一段文字。
4. 在版本清單點剛剛的快照 → **預覽** 內容 → **還原**（還原前會自動把當前內容也存成 restore-backup，所以還原可再反悔）。

**講解重點**：「自動存檔＋手動快照＋可逆還原，改壞了不怕。」

## 場景 12 — 匯出：HTML / 台灣論文 PDF / Word / LaTeX / Markdown ⭐

**操作**
1. 工具列點 **匯出（Download）** 開面板。
2. **模板** 選 **台灣論文（twthesis）**，勾 **包含封面**，填雙語封面欄位（已預設長庚大學/資管系/碩士論文/指導教授 張禾坤 博士/研究生 盧建霖）。
3. 依序示範各格式按鈕：
   - **HTML 預覽**（眼睛）→ 新分頁開出排版好的網頁版（公式有渲染）。
   - **PDF（台灣論文）**（FileDown）→ 後端 XeLaTeX 編譯，新分頁開出 PDF：**第一頁就是雙語封面頁**，內文中文正常、含章節編號與內文引用。
   - **DOCX** → 下載 Word（含內文引用＋參考文獻）。
   - **LaTeX** → 下載 .tex。
   - **Markdown / 純文字** → 下載對應檔。

**講解重點**：「同一份內容一鍵輸出五種格式；PDF 走真正的 XeLaTeX 排版，直接產出台灣碩論格式（含雙語封面、中文字型）。」
**實測**：六種格式全部成功，PDF 158KB、封面與中文內文排版正確（XeLaTeX + Noto Serif CJK 已內建於後端映像）。

## 場景 13 — 專注模式、深色模式、語言切換

**操作**
1. 工具列點 **專注模式（Focus）** → 隱藏側欄/工具列/網站列，置中窄欄沉浸寫作；右下角浮鈕可全螢幕；`Esc` 離開。
2. 右上 **深色／淺色** 切換 → 整站主題即時切換（記憶在 cookie）。
3. 右上 **語言（地球）** 切到 **English** → 整個介面變英文（網址變 `/en/editor/...`），再切回繁中。

**講解重點**：「完整的 i18n（中／英）與深色模式、專注寫作模式——產品完成度。」

## 收尾（對教授講的一段話，供參考）

> 「整體來說，這個編輯器把『寫論文』從打字工具升級成有 AI 協作的工作站：寫的時候有補全、改寫、引用查證；寫完有缺陷檢查抓論證結構問題、文法 lint 抓中文細節；最後一鍵輸出台灣碩論格式的 PDF/Word。核心差異化在於——它不是把全文丟給 LLM 問『幫我改』，而是**先把論文拆解成知識圖譜、再用規則逐條檢查**，所以結果可重現、講得出理由，這也是我論文實驗（ablation）要證明的假設。」

## 附錄：已知限制 / 錄影時避雷

| 項目 | 狀況 | Demo 建議 |
|------|------|-----------|
| 引用搜尋（中文 claim） | 不做語意重排，排序較亂 | **用英文關鍵字查詢** |
| 引用溯源 Ground | 需開放全文，閉源退回摘要/無全文 | 挑有 OA 全文的論文示範 |
| Relink 比對 | 門檻保守（≥0.80），比對不到保留純文字 | 講「保守、不亂連」當優點 |
| 缺陷檢查首跑 | 全新 Neo4j 偶發 TransientError | **錄影前先暖機一次** |
| 各功能速率限制 | 每文件每分鐘有上限（如缺陷檢查 6 次/分） | 別狂點，正常節奏即可 |
